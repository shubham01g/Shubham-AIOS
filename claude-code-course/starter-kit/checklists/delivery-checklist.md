# Delivery checklist

## Before you sign
- [ ] Real sample data in hand (not "we'll send it later")
- [ ] Definition of done written and agreed
- [ ] "Not included" list agreed
- [ ] Who decides, who tests, who you talk to

## Accounts: the client owns them
- [ ] Client creates the GitHub org / repo and invites you
- [ ] Client creates hosting (Vercel / Netlify) and invites you
- [ ] Client creates API accounts on THEIR card and adds keys to `.env` (or shares via a password-manager link)
- [ ] You never pay a client's API bills on your card

## Build
- [ ] Plan mode first, plan saved in the repo
- [ ] Deny rules + `.env` in place before any key is added
- [ ] Drafts / review steps before anything goes to real customers

## QA
- [ ] Claude lists everything that can go wrong (bad input, empty data, duplicates, API down, rate limits)
- [ ] Tests for each, run, pass/fail report saved
- [ ] Ran it on the client's real sample data
- [ ] The client tested it themselves

## Handover
- [ ] Plain-English README: what it does, how to run it, what to do if it breaks
- [ ] List of accounts and keys the client owns
- [ ] 3-minute walkthrough video
- [ ] Final invoice against the definition of done

## Get paid again
- [ ] Maintenance offer: bugs, model updates, monthly report
- [ ] V2 list sent
- [ ] Results tracked from day 1 (time saved, bookings, replies)
- [ ] Results review after 30 days → testimonial → referral ask
